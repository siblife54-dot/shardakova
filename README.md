# Фитнес-программа Насти Шардаковой

Статический технический лендинг на HTML5, CSS3 и Vanilla JavaScript. Без сборки,
зависимостей, API и внешних библиотек.

## Файлы

```text
index.html   — первый экран и контейнер тарифов
styles.css   — минимальное оформление и мобильная адаптация
script.js    — карточки, сообщения и переходы к оплате
config.js    — единая конфигурация трёх тарифов
README.md    — запуск, редактирование и публикация
```

Исходный `text.txt` сохранён; лендинг его не использует.

## Локальный запуск

Из корня репозитория:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте локальный адрес сервера в браузере. Установка пакетов и сборка не нужны.
Остановка сервера: Ctrl+C.

## Редактирование тарифов

В `config.js` у каждого объекта в `window.LANDING_CONFIG.plans` меняйте:

- `name` — название (оно также используется в тексте кнопки);
- `price` — цена строкой, например `"2 990 ₽"`;
- `description` — описание;
- `paymentUrl` — отдельная полная HTTPS-ссылка оплаты из GetCourse / Get Модуль;
- `telegramBotUrl` — будущая ссылка бота, пока не используется кодом страницы.

Сохраняйте стабильные ID `plan_1`, `plan_2`, `plan_3`. Вставляйте настоящую
платёжную ссылку **между кавычками в поле `paymentUrl` нужного тарифа**.
Все ссылки изначально пустые; тестовые платёжные системы не подключены.
Пустое поле показывает «Оплата скоро будет доступна» в соответствующей карточке.
Заполненное поле открывает свою страницу оплаты в текущей вкладке.
Невалидная ссылка или протокол, отличный от HTTPS, не открывается.

Данные вставляются как текст, а не HTML. Все файлы конфигурации публичны:
никогда не размещайте в них секреты, API-ключи, пароли или токены ботов.

## GitHub Pages

1. Закоммитьте файлы лендинга и отправьте их в ветку `main` этого репозитория.
2. На GitHub откройте **Settings → Pages → Build and deployment**.
3. Выберите **Deploy from a branch**, ветку **main**, папку **/ (root)** и **Save**.
4. Дождитесь успешного развёртывания Pages и откройте адрес, показанный GitHub.
   Стандартный адрес: `https://siblife54-dot.github.io/shardakova/`.

Стили и скрипты подключаются относительными путями `./…`, поэтому работают
и с префиксом репозитория, и в корне собственного домена. Сборка и SPA-роутинг
не требуются. Сайт пока не опубликован автоматически этими инструкциями.

Для собственного домена позже укажите его в **Settings → Pages → Custom domain**,
настройте DNS по актуальной инструкции GitHub и включите **Enforce HTTPS** после
выдачи сертификата. Файл `CNAME` заранее не добавлен: домен заказчика неизвестен.

## Оплата и Telegram: следующий этап

Готовы три независимые кнопки и поля ссылок для каждого тарифа. Для подключения
страниц оплаты достаточно заполнить `paymentUrl` реальными ссылками.

Отдельно предстоит настроить продукты и заказы в GetCourse / Get Модуль,
серверную интеграцию, проверку подлинности уведомлений провайдера и факта оплаты,
сопоставление заказа с тарифом и пользователем Telegram, выдачу доступа ботом.
Секреты этой интеграции должны храниться на сервере.

Планируемый путь: выбор тарифа → оплата → Telegram → серверная проверка оплаты →
доступ согласно купленному тарифу. Одно поле `telegramBotUrl` этот процесс
не подключает. Сейчас сайт не перенаправляет в Telegram и не выдаёт доступ.

GitHub Pages обслуживает только статические файлы. Параметры URL, локальные данные
браузера и редирект не являются подтверждением оплаты. Никакой логики «успешной
оплаты», API GetCourse, webhook или обхода серверной проверки здесь нет.

## Проверка после изменения конфигурации

- Проверьте заголовок, три карточки и якорь «Выбрать тариф».
- Нажмите каждую кнопку с пустой ссылкой: должно появиться сообщение без перехода.
- После добавления настоящих ссылок убедитесь, что каждая кнопка ведёт к своему
  тарифу. Саму оплату и выдачу доступа проверяйте отдельно при интеграции.
- Проверьте узкий мобильный экран и ПК, отсутствие горизонтальной прокрутки,
  доступность кнопок с клавиатуры и отсутствие ошибок в консоли браузера.
